Surprise wins

Three items that were not on the planned ship list but landed inside the sprint and meaningfully changed the platform's posture.

1. Email-noise audit catch

User reported a "useless email storm". We audited the last week of email log and found 71 of 76 emails were MediumCpuUsage in a force-escalate loop. Root cause was the recurrence-gate (US-5.8) threshold over-firing. One-line config fix in alertrules.yml.j2 raising llm_dismiss from 2 to 10 (monitoring-project db79ee7), then ansible-applied. Closes a real operator pain point with surgical precision. The Alerts sidebar page 9ac4b51 now surfaces noise candidates so we catch the next one earlier.

2. v2 cutover landed inside the sprint

v2 was planned as a Sprint 5 promotion candidate. Supervisor approved 2026-05-22 and the surface has been stable since, so we promoted it Sprint-4 day-13 (0b05ecc). /dashboard became the canonical URL; the v2 prefix was dropped the morning of 2026-06-02 in a17be59 after the surface settled, with legacy /dashboard/v2/* paths 301-redirecting for any lingering bookmarks. Sprint 5 no longer needs a "front cutover" line item.

3. Undocumented RDS database found

During the AWS migration backup sweep, the backup agent found a MySQL database app_db (116k rows) on RDS with zero backups and no mention in any documentation. Now dumped and verified in /root/aws-migration-backup/stateful-data/rds/. Caught a real data-loss risk before the migration cutover.

What we would do differently

Bake real-induction into the day-of-ship checklist

DA-3 and SF-5 were pushed to the GPU host with unit tests green, but real-induction acceptance lagged the code-ship by a day because Tailscale SSH was flaky during the final sprint days. Lesson: stress-induction should be part of the day-of-ship checklist, not next-day cleanup. For Sprint 5 we will pre-stage the induction script and run it inline with the deploy.

Tune known knobs before the user complains

The email-noise audit could have happened earlier. The recurrence-gate threshold was a known knob from US-5.8 design; we just did not tune it until the user surfaced the pain. The Alerts sidebar page now exposes noise-ratio per alertname so the next tuning pass is proactive, not reactive.
