What “bull’s-eye” means here (so it holds at the jury)

  • Precise root — the LLM named the exact mechanism (e.g. OOMKilled, memory limit too small, raise to 2Gi; Hibernate startup failure tied to the rollout 4 min before). Counted when the reason is in kube-state-metrics or the logs.
  • Correct class, honest defer — for ImagePullBackOff / unschedulable, the reason lives only in pod events, so the LLM named the outage correctly and handed the operator the exact describe command instead of guessing. Correct and grounded, not a miss.
  • Wrong / fabricated — a cause not supported by evidence. Count across the whole campaign: 0.

Bull’s-eye = precise root + correct-class-honest-defer (both are “right, zero fabrication”). The precise-root subset is reported separately below.

Test-audit-RCA observations (no fixes applied — improvement levers)

  • Cause depth tracks the evidence. OOM, crash and config errors get a precise named root (reason is in kube-state-metrics / logs). ImagePullBackOff and unschedulable get the outage named + a diagnostic step, because the reason lives only in pod events. Lever: a bounded-agency “describe pod / last_terminated_reason” call would name image-pull and scheduling roots directly. Recorded, not fixed.
  • Same Hibernate symptom masks the DB sub-cause. Wrong DB name, wrong password and wrong host all surface as the same Hibernate dialect startup error, so the LLM names the correct class (deploy misconfiguration) but not always the exact sub-type. Honest and defensible.
  • RollingUpdate protects availability. A bad image / nodeSelector on a 1-replica deploy does not cause an outage by itself; the broken template must take over. A no-op deploy that never goes Ready is correctly a non-incident.
  • Drain3 is silent on known templates. Flag-driven failures it has already learned do not re-alert (novelty-not-volume). Genuine novelty (the malformed-payload flood) is the positive path.
  • Single-GPU serial backlog. An isolated alert investigates in ~30–45 s (the ~38 s design figure). Under this campaign’s deliberate 10-service simultaneous burst the median rose to ~61 s with a tail to several minutes, as one GPU drained the queue serially. A single-host characteristic, not a per-investigation regression; production scales the model/host (L4).
